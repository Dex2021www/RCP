# RCP — быстрый копировщик для Проводника Windows 11

Фоновая утилита: перехватывает **Ctrl+V только в Проводнике** (когда в буфере файлы после
Ctrl+C), сама копирует/перемещает файлы в многопоточном режиме и в конце **сверяет результат
побайтово** (бит-в-бит). Живёт в трее; из интерфейса — только мини-окно прогресса,
которое можно выключить.

## Как это работает

1. Низкоуровневый хук клавиатуры (`WH_KEYBOARD_LL`) видит нажатие **V с Ctrl** (без Shift/Alt/Win).
2. Если фоновое окно — Проводник (`CabinetWClass`/`ExploreWClass`) или рабочий стол
   (`Progman`/`WorkerW`), фокус не в поле ввода (переименование/адресная строка), утилита не на
   паузе и в буфере обмена есть файлы (`CF_HDROP`) — нажатие **поглощается**, чтобы Explorer не
   запускал своё медленное копирование.
3. Активная папка берётся через COM (`IShellWindows` → `LocationURL`), файлы — из буфера обмена.
4. Движок копирования:
   - обход дерева — `jwalk` (параллельный);
   - копирование файлов — `rayon`, все файлы одновременно (по потоку на логическое ядро
     процессора),
     большие файлы первыми — равномернее загрузка;
   - буферы по 16 МиБ (по одному на поток, переиспользуются), предвыделение размера
     файла (`set_len`) против фрагментации;
   - файлы крупнее 128 МиБ режутся на 3 части и льются параллельно, крупнее 1 ГиБ —
     на 4 (позиционные `seek_read`/`seek_write`);
   - папки создаются параллельно;
   - сохраняются даты файла/папок (создание/изменение/доступ) и атрибуты
     (hidden/system/archive, read-only для файлов);
   - длинные пути не проблема — везде `\\?\`-префикс.
5. **Сверка бит-в-бит конвейером**: каждый файл сразу после записи побайтово
   сравнивается с источником тем же потоком — пока оба в кэше, без второго прохода
   по диску. В итоговом уведомлении — «Сверка бит-в-бит: OK» и статистика.
6. Ctrl+X + Ctrl+V (перемещение): в пределах тома — мгновенный rename; между томами —
   копирование + сверка + удаление источника только если сверка прошла без ошибок;
   вырез и вставка в ту же папку — ничего не делает (как Explorer).
7. **Вставка в ту же папку, где лежит источник** — как Explorer, создаётся
   «имя - Копия.ext», при повторе «имя - Копия (2).ext» и т.д. (для папок —
   «папка - Копия»), с той же побайтовой сверкой.
8. **Выделение вставленного**: после завершения вставленные файлы/папки
   выделяются в Проводнике (как после родной вставки) — с фокусом и
   автоматической прокруткой к ним. Работает и для
   мгновенных перемещений; на рабочем столе выделение пропускается.

Оркестрация заданий — tokio (очередь, `spawn_blocking`), отмена — `CancellationToken`
из tokio-util. Буферы копирования/сверки выделяются один раз на поток и живут всё время
работы программы (TLS) — мелкий файл «залетает» в готовый буфер без аллокаций.

## Окно прогресса

Мини-окно в правом нижнем углу: **всегда поверх всех окон** (WS_EX_TOPMOST, больше не
прячется под Проводник), **тёмная тема** как у тёмного Explorer — тёмный заголовок
(DWM immersive dark mode), фон #202020, светлый текст Segoe UI, кнопки и прогресс-бар
в стиле DarkMode_Explorer с акцентом #4CC2FF. Показывает цель, сколько файлов и байт
скопировано из скольких, процент, скорость, время, текущий файл. Кнопки **«Пауза»**
(честно замораживает передачу между кусками, как Explorer; повторный клик — продолжить)
и **«Отмена»** (закрытие окна — тоже отмена). По завершении показывает итог
(«бит-в-бит OK», скорость, объём) и исчезает само. Обновляется таймером GUI-потока
8 раз/с — ни одного лишнего потока.

Галка **«Окно прогресса»** в меню трея. Когда выключена — окно не создаётся, таймер не
тикает, счётчики файлов/имён/процентов не считаются: движок работает в «слепом» режиме,
итоги приходят уведомлением-балуном как раньше.

Диагностика внешнего вида: `rcp.exe --uitest` — окно с симулированной передачей
(~10 с, без хука и синглтона).

## Сборка

Нужны стабильный Rust (проверено на 1.99) и инструменты сборки MSVC — компонент
«Разработка классических приложений на C++» из Visual Studio Build Tools.

```
cargo build --release
```

Готовый exe: `target\release\rcp.exe`. Самопроверка движка (копирование + сверка +
негативный тест детектора):

```
rcp.exe --selftest
```

Официальные бинарники собирает сам GitHub. Если собираете exe сами и
хотите им поделиться — берите `build-release.cmd` вместо `cargo build --release`:
обычная сборка зашивает в exe абсолютные пути машины сборщика (сообщения паник
зависимостей содержат пути вида `C:\Users\<имя>\.cargo\...`), скрипт их вырезает.

## Запуск и автозапуск

Просто запустите `rcp.exe` — он поселится в трее (второй экземпляр не запустится).
Для автозапуска: Win+R → `shell:startup` → положите туда ярлык на `rcp.exe`.

## Управление (правый клик по иконке в трее)

- **Пауза** — Ctrl+V снова обрабатывает сам Explorer (обычное медленное копирование);
- **Окно прогресса** — показать/скрыть мини-окно копирования;
- **Остановить текущее копирование** — отмена с отчётом «скопировано X из Y»
  (то же самое — кнопка «Отмена» или закрытие окна прогресса);
- **Выход**.

Свой бинд: `pub const BIND_VK` в `src/hook.rs` (0x56 = 'V') и набор модификаторов в `mods_ok()`.

Диагностика: `rcp.exe --tabs` — дамп окон/вкладок Проводника (активная вкладка,
доступность shell view, текущее выделение); `rcp.exe --select <папка> <имя...>` —
ручная проверка выделения элементов.

## Журнал

`%TEMP%\rcp.log` — задания, ошибки, итоги.

## Замечания и ограничения

- **Скорость упирается в Defender**: реальное время сканирует каждый новый файл. Если
  добавите часто используемые папки-приёмники в исключения Defender — скорость вырастет
  в разы.
- Вкладки Проводника поддержаны: активная вкладка определяется по заголовку окна
  (он начинается с её отображаемого имени, локализация учитывается через shell),
  с резервным проверкой видимой shell view; копирование уходит именно в активную
  вкладку. Диагностика открытых окон/вкладок: `rcp.exe --tabs`.
- Вставка в «особые» места (Этот компьютер, поиск, zip-папки) не поддерживается —
  придёт уведомление об ошибке.
- Копирование в защищённые папки (`C:\Program Files` и т.п.) требует запуска rcp от
  администратора.
- Символические ссылки пересоздаются как ссылки (нужны привилегии разработчика),
  NTFS-сжатие/шифрование содержимого не переносится (содержимое — байт-в-байт).
- Существующие файлы в приёмнике перезаписываются (как robocopy); исключение —
  вставка в ту же папку, где лежит источник: тогда создаётся «имя - Копия».
